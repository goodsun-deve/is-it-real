# 구매자 전용 페이지 (스마트스토어·그립 판매용)

`/buyer.html` — 공개 무료 링크(`/`)와 완전히 분리된, 코드 입력이 필요한 페이지입니다.
기존 `index.html` / `api/analyze.js`는 전혀 수정하지 않았고, 아래 파일만 새로 추가했습니다.

```
buyer.html            구매자 코드 입력란이 있는 검사 화면
api/analyze-buyer.js  analyze.js와 로직은 동일 + 코드 확인 단계만 추가된 별도 API
```

## 환경변수 추가

| 이름 | 필수 | 설명 |
|---|---|---|
| `ACCESS_CODES` | ✅ (buyer.html을 쓰려면) | 유효한 구매자 코드, 쉼표로 구분. 예: `APPLE2026,BANANA2026` |

Vercel 대시보드 → 프로젝트 → Settings → Environment Variables 에서 추가하고, 반드시 **재배포**해야 적용됩니다 (`OPENAI_API_KEY`를 추가했을 때와 같은 방식입니다).

- 코드는 대소문자 구분 없이 비교합니다.
- `ACCESS_CODES`를 설정하지 않으면 buyer.html은 모든 코드를 거부합니다 — 안전 기본값입니다.
- 로그인·결제 연동이 없으므로 이건 "공유 비밀번호" 수준의 보호입니다. 코드를 아는 사람은 누구나 쓸 수 있고, 1회성 사용 제한은 없습니다 (사용 기록을 저장할 DB가 없는 현재 구조의 한계).
- 코드가 유출되면 Vercel 환경변수에서 그 코드를 목록에서 지우고 재배포하면 즉시 무효화됩니다.
- 판매 배치마다 다른 코드를 발급하면, 유출 시 해당 배치 코드만 지우고 나머지는 유지할 수 있습니다.

## 운영 흐름

1. 스마트스토어·그립 상세페이지에는 `/buyer.html` 링크를 적지 않습니다 (페이지 자체에 검색엔진 수집 금지 설정은 돼 있지만, 링크 자체를 공개하지 않는 게 원칙입니다).
2. 결제 확인 후, 구매자에게 `/buyer.html` 링크와 그 시점에 유효한 코드를 함께 전달합니다 (스마트스토어 발송 메시지, 그립 톡톡 등).
3. 코드를 교체하고 싶으면 `ACCESS_CODES` 값을 바꾸고 재배포 — 기존에 그 코드를 받은 구매자는 더 이상 쓸 수 없게 됩니다.

## 기존 공개 링크(`/`)와의 관계

`/`(index.html)와 `/api/analyze.js`는 이 작업으로 전혀 바뀌지 않았습니다. 지금처럼 계속 로그인·코드 없이 누구나 쓸 수 있는 무료 링크로 남아 있습니다. `/buyer.html`은 그 옆에 추가된 별도의 입구일 뿐입니다.
